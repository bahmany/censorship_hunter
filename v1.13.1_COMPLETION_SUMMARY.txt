==============================================================================
                          UPDATE FLOW ARCHITECTURE
==============================================================================

┌───────────────┐
│ CHECK UPDATES │ → Query GitHub API → Get UpdateInfo
└───────────────┘
        ↓
┌───────────────┐
│   DOWNLOAD    │ → HTTPS from GitHub → Track progress (0-100%)
└───────────────┘
        ↓
┌───────────────┐
│    VERIFY     │ → Calculate SHA-256 → Compare with digest → Reject if bad
└───────────────┘
        ↓
┌───────────────┐
│   APPLY       │ → Platform-specific → Atomic operations → Process management
└───────────────┘
        ↓
┌───────────────┐
│  RELAUNCH     │ → Start new exe → Exit old process → Zero-downtime
└───────────────┘

==============================================================================
                          QUICK START GUIDE
==============================================================================

For Users:
  1. Wait for v1.13.1 release
  2. Application will auto-detect update
  3. Click "Update Now" when prompted
  4. Application auto-relaunches
  5. Done! ✅

For Developers:
  1. Build: cd hunter_cpp && mkdir build && cd build
  2. Configure: cmake .. -DHUNTER_VERSION_STRING=1.13.1 -G Ninja
  3. Build: ninja
  4. Test: ./tests/test_auto_updater
  5. Deploy: Follow DEPLOY_v1.13.1.md

For DevOps:
  1. Build the application
  2. Create GitHub release
  3. Upload assets
  4. Verify SHA-256 checksums
  5. Deploy to production
  6. Monitor for issues
